**Goal:** On the default newworld config (FE1F surface default-on since `be0e02cb`), the
boot dies at the **68k PC-desync wall** (DSAT-WALL-RECON.md, the post-FE1F frontier): the
DR dispatches the word at ROM **0xe412** — the pc-relative displacement word `ff8e` of
`lea.l $5000e3a0(pc),a2` at 0xe410 — as an opcode. 0xFF8E is line-1111 → vector 0x2c →
SysError ID 10 → the unseeded DS-alert path recurses ~12,000 iterations, grinding A7 from
0x103ffaxx below RAMBase → SIGSEGV ea=0x40000fffff42 at the DR push site 0x504661a0.
**The $36-callout-return theory is RETIRED** — the $36 round trip is clean end-to-end
([PROBE✓], DSAT-WALL-RECON Q-D1); what is broken is the *resume/re-dispatch machinery*
in the window after it. This milestone is **(i)' per the recon's verdict: fix the desync**
— root-cause the re-dispatch at e410+2, fix it in the delivery/resume machinery (or DR
dispatch-state restoration), and verify the boot passes 0xe410 with **no SysError ID 10**.
It is NOT a $36 semantics fix and NOT a DSAT/SysError-surface fix ((ii) stays recorded,
not scheduled). Surface-scoped like the predecessors: the desync root-caused + fixed +
the boot advances; the next wall is captured, named, and stopped on per the stop-rule.
Paravirtual byte-identical throughout (with one EXPLICIT caveat: if the root cause is the
`trap_return` patch itself, the fix MUST be newworld-profile-gated — the patch is
load-bearing on the legacy/paravirtual path; see Architecture).

**The captured baseline (the milestone's opening evidence; re-confirm once before Task A
— "byte-identical DSAT baseline" means exactly these fields, jitter counters excluded):**
deterministic record anchors (±1 jitter class): e3e0 entry **#3390830**; $31 round trip /
ExpandMem slot fill `[0x100037dc]:=0x00120001` **#3391078/79**; ROM-PPC TVector-world
