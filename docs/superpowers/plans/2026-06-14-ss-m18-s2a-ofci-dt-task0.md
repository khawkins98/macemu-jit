## The OF-CI/DT unit-test SPEC (dispatch-resolution + DT-coverage; no boot, no real backends)

> Task-0 produces the SPEC + I/O contract + pinned oracle dependency (no code, no fixture file generated). The S2a-impl milestone builds it at `SheepShaver/src/machine/test_openfirmware_ci.cpp` (Makefile target pre-wired by the coordinator at impl-kickoff).

- **What it is.** A standalone, no-boot test that drives `of_ci_callback()` with the enumerated call battery and asserts (1) **unresolved-call counter = 0** across all 21 direct services + 14 `call-method` names + the 3 `interpret` literals; (2) **DT coverage** — every `finddevice` path resolves to a node, every `getprop`/`getproplen` key returns the CORE99 value (or the documented provisional for the Q-S2a.3 residue), and `nextprop` enumerates the full child/property set (the runtime `nextprop`×397 surface, NOT only the static ×1).
- **The `call-method` backends are INJECTED (decoupled, the `dev_cuda`/`adb_stub` pattern).** The test supplies **test-double callbacks** for `read-blocks`/`write-blocks`/`block-size` (disk), `/mmu` `claim`/`translate`/`map`, and the display methods. The test asserts the backend was *invoked with the decoded args* — it does NOT exercise real disk/mmu/fb (those are S2b/S1). This keeps the harness `kpx_cpu`-free, matching the existing machine tests.
- **The expected-call-sequence oracle.** The Q3 `[QEMU-BEHAVIORAL]` Trampoline trace is the ground-truth sequence. The test battery is built from the *enumerated static set* (177/177 + 24/24) widened by the runtime divergence (the dynamic getprop/finddevice/nextprop residue). **QEMU OpenBIOS is the dispatch-idiom oracle ONLY** — its DISPATCH STRUCTURE (CHRP `{name,n_args,n_rets,args…}` array decode at `[r2-0xc]`), never its addresses (address-oracle LAW). No QEMU MMIO address is a reference value.
- **Inputs (the battery).** (a) each direct service with a representative arg set from the trace; (b) each `call-method` name against an opened ihandle test-double; (c) the 3 `interpret` literals; (d) the **adversarial DT-coverage case** — the full `nextprop` walk of `/mac-io` and its children + the 8 dynamic getprop keys: if the synthesized DT can't enumerate these, the Trampoline's runtime tree-walk would stall, so the test must drive the *runtime* breadth, not just the static set.
- **Predicates.** `unresolved_calls == 0` (the headline gate G2a.b); `dt_answered(every finddevice/getprop/nextprop) == true` (G2a.c); each injected `call-method` double observed the decoded args. The `interrupt-map`/`-mask` rows assert the QUERY resolves and the SHAPE matches the Q-S2a.3 pin (or the documented provisional if residue).
- **What it retires vs does not.** It retires "the OF-CI surface is unresolvable / the DT can't answer the producer" as a *dispatch-and-coverage* property. It does NOT prove the real Trampoline boots (that needs S2b's loader + S1's `/mmu` + a real boot — explicitly out of S2a scope), and it does NOT validate the interrupt-routing VALUE end-to-end (that is the NanoKernel→CGRP path, owed to the program-level boot after S1+S2b+S3).

## Stop-rule (triggers named in advance; one-iteration mechanics)

1. **#3 (program) — "Guess the `interrupt-map`/`-mask` tuple shape."** Q-S2a.3 pins from CORE99 ONLY; if the doc lacks it, the answer is a flagged-residue-to-S2b, NEVER a fabricated cell-shape. Reconstructing it from the QEMU value is forbidden (address/shape-oracle caveat).
2. **#6 (program) — QEMU-as-address-oracle.** No QEMU MMIO address is a reference value for our DT (QEMU MacIO is a firmware-assigned PCI BAR; ours is fixed `0xF3000000`). QEMU OpenBIOS is a *dispatch-idiom* and *relative-region* oracle only.
3. **"Run a QEMU boot / disasm the NK to resolve an OF call or the DT shape."** STOP — the OF inventory is statically closed (177/177 + 24/24, 0 unresolved); S2a is boot-disjoint and unit-tested. ZERO boots, ZERO NK disasm.
4. **"Start writing `openfirmware_ci.{cpp,h}` / the DT model / the test body mid-Task-0."** This Task-0 writes no `SheepShaver/src/**`; the test is SPEC'd here, BUILT in S2a-impl.
5. **"Implement the real `/mmu` or `read-blocks` backend in S2a."** Those are S1/S2b. S2a wires the injected-callback seam + test doubles only; claiming backend completeness is a false-clean.
6. **"Drop the static-vs-runtime divergence (treat `nextprop`×1 as the surface)."** The runtime tree-walk (`nextprop`×397, +8 dynamic getprop, +2 dynamic finddevice) is the DT-coverage obligation; ignoring it is a recon-before-code violation that would surface as a boot stall in S2b.
7. **"Proceed to S2a-impl on a blocking RESIDUE-PASS (Q-S2a.1 or .2)."** A residue on the verb-set or DT-coverage BLOCKS its dependent impl task; the coordinator re-scopes first. (A Q-S2a.3 tuple-shape residue is the expected discovery and is handed to S2b — it does not block S2a dispatch/DT-query work.)
